# 網站巡檢與異常排查

[简体中文](README.md) | **繁體中文** | [English](README.en.md)

> 這份由 `scripts/docs.ts` 從簡體中文版自動轉換，改內容請改簡體中文版。

外部機器檢查網站，故障交維護 Agent，恢復後收尾。每 5 分鐘執行固定腳本；正常時不呼叫模型，異常持續時不重複派活或發通知，恢復時更新原卡片。

## 怎麼啟用

1. 把本目錄複製到 `~/.agent-autoloop/work/website-watch/`，目錄僅本人可讀。執行檢查腳本的電腦要在被檢查服務之外，避免伺服器停了連巡檢也一起停。
2. 把 `SKILL.md` 放到 `~/.codex/skills/website-watch/`；Claude Code 放到 `~/.claude/skills/website-watch/`。
3. 合併 `rules.json` 的 `sources`、`agents`、`channels` 和 `rules`。兩處 `worker` 改成接單電腦；檢查規則的 `cwd` 指向複製的範本目錄，排查規則的 `cwd` 指向自己的程式碼目錄。時區用 `Asia/Shanghai`。
4. 修改 `site.json`：填寫自己的站點編號、名稱、健康 URL 和響應必須包含的文字。示例域名只是佔位，不能作為驗收目標。地址不帶帳號密碼、查詢參數或片段；需要鑑權的健康介面應先按自己的專案約定改檢查腳本。
5. 權限：`read`。維護 Agent 預設只讀原生代碼；HTTP 請求由固定檢查腳本完成。要查線上日誌或執行已批准動作，需要在專案 main 的維護手冊登記已有工具，不能從事件裡取得命令。
6. 執行 `agent-autoloop check`，再在專用測試中控台接一個本地假 HTTP 服務，驗證異常、持續異常、恢復。不要拿真實網站停服來測試。

## 檢查口徑

成功必須同時滿足 HTTP 200 和包含 `contains` 指定的非空文字。不跟隨跳轉；連線、讀取超時（20 秒）或內容不符都記為異常，不輸出響應正文。這個例子首次失敗就報告；不沿用內部監控的“連續三次”計數，以免範本另維護一套狀態。若網站已有成熟的告警去抖，應直接把其告警作為事件接入。

未恢復的異常儲存在中控台的問題通知卡片中。腳本只核對當前站點對應的卡片；卡片還開著就不重發，恢復時結案並行 `site.recovered` 事件讓維護 Agent 核對剩餘事項。**不要提前點“已處理”關閉仍未恢復的異常卡片**：手動關閉表示這次提醒已處理，下一次檢查仍失敗會再次報告。同一檢查組只用於這一個站點，名稱保持穩定；多站點各使用獨立的來源、規則名、group 和站點編號；每套的 `emits.source` 必須只對應本站處理規則的 `when.source`，避免把其他網站的告警派到錯誤專案。

HTTP 恢復不代表瀏覽器或所有業務功能通過。需要本人恢復網頁連線、登入或權限時，維護 Agent 用 `ask` 留下待辦；這一輪結束，不反覆重跑業務。

## 飛書通知

規則預設登記 `feishu` 通道。把 `ou_REPLACE_ME` 換成本人的 open_id；在已有 `config.json` 的 `channels.feishu` 配上這個人的 `user` 和已有通道金鑰。複用已執行的飛書通道，不另開監聽。尚未接入時按[通道設定](../../../skills/agent-autoloop/SKILL.zh-TW.md#接一個通道)完成；設定涉及新金鑰或權限時先取得本人授權。

讀取業務資料使用本人身份，通知使用機器人身份。預設只發給本人；一箇中控台預設把卡片交給它設定的所有通道；含私人資料的規則寫上 `channels`，只發到本人私聊的通道，不要混入共享群通道。不要把金鑰、實際 open_id、表格 token 或業務資料提交到倉庫。
