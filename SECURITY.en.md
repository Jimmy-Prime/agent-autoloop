# Security
[简体中文](SECURITY.md) | [繁體中文](SECURITY.zh-TW.md) | **English**

If you find a security issue, tell me privately through GitHub [Security Advisories](https://github.com/Jimmy-Prime/agent-autoloop/security/advisories/new). Do not open a public issue.

The private vulnerability report form needs the repository to be public and that feature to be enabled. If the form is unavailable, say only, in an Issue, that you need to contact a maintainer privately to report a security issue, and wait for a maintainer to arrange a private channel. Do not paste vulnerability details, keys, or business data.

A private report should include the affected commit, the environment, the smallest reproduction steps, and the possible impact. Redact logs and screenshots first. Security issues are currently verified and fixed on the latest `main`. The fix reaches users in the next Release. A severe issue gets its own small release. There is no separately maintained long-term support branch, and no fixed response time is promised.

## Boundaries

- The hub listens only on this machine by default. To expose it, put an HTTPS reverse proxy in front.
- The installer and the hub set the data directory to `0700` on macOS/Linux when they start. On Windows, they use a protected ACL that keeps only the current account and SYSTEM. They also correct a directory that already exists. The database, event bodies, and run output are therefore not open to other system users. Codex's dedicated Windows sandbox account is additionally granted read access only to the `context.json` task data, not the master key, round tokens, or other files. This does not isolate processes under the same system account.
- An event cannot decide who it is handed to, which directory, which Skill, or what permissions. Only `rules.json` decides those. Titles and bodies other people wrote do not enter the prompt. They go only into a file marked as data. The prompt has only types, IDs, and links whose characters have been checked. This does not stop every prompt injection. The agent still reads what other people wrote. The default permission is `edit`. Before you give `full`, think through what this agent can reach. Things with side effects go through `askFirst`.
- `access` is mapped to CLI permissions by a dedicated agent plugin. `command` does not limit permissions for an arbitrary program. `read` on an ordinary agent does not mean it cannot read keys on this computer. To isolate keys, use a separate system account or a container.
- Ordinary access keys are stored only as SHA-256. A local `master.key` also derives the tokens for rounds and card links. If `master.key` is empty or incomplete, the hub refuses to start. It will not sign links with that key, and it will not replace it with a new one on its own. The worker does not pass hub credentials through the prompt, the context file, or environment variables. Which files can be read under the same system account is still decided by the agent sandbox. What a receipt can affect is described in `docs/protocol.en.md`.
- Anyone who has a card link can answer that one card. It is valid for 7 days from when the card was created. After it expires, the card content is no longer shown either. Links are sent only to channels configured with `"links": true`.
- This project only starts official command-line tools that you installed and signed into yourself. It does not touch, store, or relay their login credentials.
- Browser capabilities come from the agent's own tool configuration. A dedicated entry point is taken only from a trusted rule or Skill, not from a command in the event body. The hub does not automatically grant browser permissions or take over a desktop session. A connection or verification the owner has to restore is handed back with `ask`, and items not yet checked are kept.

## Plugins and delivery

Plugins are local code the person who installed them trusts. A plugin of the same name in the install directory takes priority. `agent-autoloop add` only clones. It does not run install scripts, but loading the entry point later executes the plugin. An event cannot name a plugin, repository, command, or permission.

ACP authorization depends on the agent following the protocol. The specification allows it to act without asking. `access` covers only operations it comes and asks about. The bridge decides only from the structured tool kind, the edit path, and the one-time option. It does not provide a file or terminal service. MCP uses an identity that already exists on this machine and offers only the seven operations the protocol lists. It does not distinguish callers. All of them are recorded as the owner. Do not put it in the user-level configuration of a CLI the worker starts, or a round can answer its own card. Revoking a key ends its long polls and log subscriptions immediately. Round tokens are separate.

Delivery accepts only a branch inside the repository the rule names, and only into main. Project settings, review requirements, and a replacement review command are all read from main. A PR only downloads Git objects and produces a text diff. It does not check out or run the PR's code, tests, configuration, or hooks. An octopus merge whose content the review cannot see is reported as a problem and is not allowed through. Codex, by default, ignores user configuration and memory and uses a read-only isolated snapshot. A custom review command is the project maintainer's responsibility, and it has to constrain permissions the same way.

A successful review state is written only after the full checks for that same commit pass. When the review finds a problem, it writes a failure, and that same commit is not reviewed a second time. Before merging, it checks the commit, the target branch, the labels, and main again. Adding `deliver-review` while waiting for checks also blocks the merge. If clearing labels succeeds only in part, a retry still does not merge a review-only PR. The project still needs its own merge rules configured on GitHub. The plugin cannot stand in for platform permissions. A merged PR that still has the `deliver` label only goes on to verify Ship and the live health version. It is not merged again. The health URL requires HTTPS by default. Only an explicit test switch allows HTTP to 127.0.0.1. A redirect, or a version that does not qualify, does not prove it is live.

The desktop notification body includes the card title the agent wrote. It is passed only as an argument to `osascript` or `notify-send`, after `--`, and it is not spliced into a script. Webhook templates have no external idempotency guarantee. A send that succeeds while its report is lost may repeat. Answering through a link means holding the link is authorization. Do not send a link anywhere public. A Feishu app can keep only one card-event listener. Tests in this repository use only a fake CLI.

## Recipe data

Public templates contain only fictional data, example domains, and placeholder identifiers. Feedback content, page responses, and Feishu data cannot specify a command, directory, permission, or recipient. The current state of feedback, and the decisions, are read again from a trusted business interface. Feishu reports and tables are read as the owner. They cannot switch to a bot identity to fill in data the owner cannot see. Summary input is kept in the owner's private directory and is replaced only after a complete read. Notifications do not carry sensitive body text.

Who a channel delivers to belongs to the whole hub. A rule cannot pick recipients on its own. A hub that handles private feedback and reports should connect only to channels the owner can see. Do not connect them to a shared group. A new connection reuses the user's own identity and authorization. Do not copy internal deployment configuration, keys, or business logs.

The browser handoff template's command array, target URL, and allowed actions come from the owner's trusted configuration. They are passed as arguments. Task text is not handed to the shell to interpret. Allowed actions are the task scope given to the agent, not an extra system sandbox. The actual tools and account permissions are still decided by the existing runtime. A session id uses only the value the entry point actually returned. If it is interrupted, or the result is unclear, check first. Do not blindly repeat browser actions that have side effects. The template does not change an application's internal state, does not automatically start a new account authorization, and does not bundle one computer's browser repair script.

## Logs and recovery

Who is allowed in, the channel answerer and the original message, the scope of a round token, duplicate receipts, and card answers all have behavior and consistency checks. `sim/invariants.ts` holds the invariants shared by the simulation and the enumeration. The nightly check also sends SIGKILL to a real SQLite process. The scope is process crashes and a limited set of scenarios. It is not a proof of recovery after power loss, or a complete security audit.

`kernel/` does not read a clock and does not draw random numbers. The decision, appending the facts, and `evolve` updating the projection finish in the same WAL + FULL transaction. The hub replies only after that commit. A normal start reuses the projection, which carries a cursor and an id high-water mark. When the format fingerprint changes, it rebuilds from the log one fact at a time, and it does not change old facts. `agent-autoloop why 42` shows one round's events, rules, and receipts. `GET /v1/stream?after=42` lets the owner's client resume by sequence number. Back up with `agent-autoloop backup [directory]`. This works while the hub is running. Restore with `agent-autoloop restore <directory>`, and stop the hub first. When a rule sets `resume`, data a round read stays in the session, and later rounds can still see it, including words other people wrote in the events. When `parallel` is not set, every event for that rule shares one session. Do not configure an untrusted source that way.

A backup contains the master key, keys from the configuration, and `secrets.env`. On macOS/Linux, the directory mode is 0700 and the files are 0600. On Windows, they inherit the directory ACL that allows only the owner and SYSTEM. Keep it the way you keep a key. A restore replaces these files and the rules. A manual backup has to keep `hub.db` together with `master.key` under the same access restrictions. The latter derives the tokens for rounds and card links. Ordinary access keys are stored only as hashes. The card-link lookup index also stores only a hash of the token.
